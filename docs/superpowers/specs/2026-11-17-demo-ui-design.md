# 本地演示页（demo UI）设计

日期：2026-11-17
状态：待确认

## 意图

作业演示需要一个在本地打开就能看到拍卖状态、并能完成「创建 → 出价 → 结算 → 提取」的网页，替代 Remix 每次手动 At Address、手填参数的流程。演示对象是本地 anvil 链上已部署的 V1/V2 合约。

## 目标

- 一条命令启动，浏览器打开即用，**不需要 MetaMask、不需要外网**
- 覆盖全部演示动作：创建拍卖、ETH 出价、ERC20 出价、推进时间、结算、提取退款/货款/平台费
- 页面直接显示：合约版本（V1/V2）、拍卖列表、每场最高价与其 USD 价值、剩余时间、结算状态
- 演示中必然遇到的「推进时间导致预言机陈旧」问题，页面上有一键刷新

## 非目标（anti-goals）

- 不接 Sepolia、不接真实钱包、不处理私钥安全（仅用 anvil 公开测试私钥）
- 不做事件历史索引、不做拍卖搜索/分页、不做移动端适配
- 不做交易确认弹窗之外的额外交互打磨

## 方案

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| A. 单文件静态页 + ethers UMD，本地 vendor | 无构建步骤、离线可用、约 300 行 | **选中** |
| B. Vite + React + wagmi | 工程化更完整，但引入 node 依赖与构建链，与「纯 Foundry 交付」的定位背离 | 否决 |
| C. 只读看板，交互留在终端 | 代码最少，但演示时要在网页和终端之间来回切 | 否决 |

## 设计

**技术栈与启动**

- 文件：`demo/index.html`、`demo/ethers.umd.min.js`（本地 vendor，保证离线可用）、`demo/README.md`
- 启动：`python3 -m http.server 5173 -d demo`，打开 `http://localhost:5173`
- 链：`JsonRpcProvider("http://127.0.0.1:8545")`，chainId 31337

**账户与签名**

- 页面内置 anvil 前 4 个账户（卖家、买家 A、买家 B、平台收款），下拉切换
- 用 `Wallet` 在浏览器内本地签名，因此**无需安装任何钱包插件**
- 页面上明确标注「仅用于本地测试链的公开测试私钥」

**地址来源**

- 启动时读取 `deployments/local.json`；若读取失败（例如从 `demo/` 目录单独起服务），页面提供手动填写各合约地址的输入区

**页面结构**

```
┌ 顶部：版本号 (V1/V2) · 链 ID · 当前账户下拉 · 刷新
├ 工具区：[推进时间 +1h] [刷新预言机] [刷新数据]
├ 新建拍卖：NFT 地址 · tokenId · 起拍价 USD · 时长(秒) · 计价代币(ETH/USDC) → [创建]
├ 拍卖列表（按 id 倒序）
│   #id · NFT#tokenId · 起拍 $X · 最高 $Y (币种) · 剩余 mm:ss · 状态
│   按钮：[ETH 出价] [USDC 出价] [结算]
│   失败时在卡片内显示 revert 原因
└ 提取面板：当前账户可提取的 退款 / 货款 / 平台费，各带 [提取] 按钮
```

**数据读取**

- `nextAuctionId()` 取得总数，逐条 `getAuction(id)` 渲染
- 每 3 秒轮询一次；操作成功后立即刷新
- 剩余时间基于本地时钟与 `endTime` 的差值，不依赖链上最新区块

**边界处理**

- 未配置 feed、预言机陈旧、余额不足等 revert 都原样显示在对应卡片的错误区
- 账户没有待提取余额时，提取按钮置灰

## 部署与版本管理

- `demo/` 目录提交进仓库（演示是交付的一部分）
- `demo/ethers.umd.min.js` 一并提交，避免演示现场依赖 CDN
